# Дашборд: главный экран

Статус: концепция дизайна, готова к вёрстке. Экран `/dashboard` из структуры проекта в `0-mvp.md`; часть требований (карточка плана обучения, статистика) относится к скоупу фазы 2 — отмечено отдельно по ходу документа.

## Информационная архитектура

Главный экран — зона **действия** («что делать сейчас»), не зона **рефлексии** («как у меня дела за последнее время»). Эти два режима использования разведены по разным местам:

- **Dashboard (главный экран)** — то, что видно сразу при открытии приложения: сегодняшняя задача + прогресс в моменте.
- **Статистика** — отдельный раздел/вкладка, посещается по желанию, не обязательный элемент ежедневного открытия.

Смешивание тяжёлых визуальных элементов (графики) с лёгким ежедневным действием (кнопка «Повторять») на одном экране конкурирует за внимание и замедляет главный сценарий — поэтому графики сюда не идут.

## Состав главного экрана

### 1. Шапка

Название приложения, иконка настроек (шрифты и пр., см. `2-design-system.md`), меню пользователя (профиль/выход). Некрупно, не в фокусе.

### 2. Приветствие и стрик

`Привет, {username}` + `🔥 N дней подряд`.

Стрик — количество подряд идущих календарных дней хотя бы с одним `review_events`. Считается агрегатным запросом по существующей таблице, отдельного хранения не требует — дёшево добавить поверх уже спроектированной модели данных из `0-mvp.md`.

### 3. Карточка «Слова» — главный элемент экрана (primary)

Самая крупная зона на экране, с таэгык-кромкой сверху (единственное место на экране, где используется эта деталь дизайн-системы — не размазывать по всему UI).

Содержимое:

- **Сегментированный progress bar** — одна полоса на всю ширину карточки, поделена на цветные сегменты пропорционально количеству слов в каждой категории:
  - изучено — `--green`
  - изучается — `--blue`
  - доступно для изучения — `--line`/`--stone`
- Число **«К повторению сегодня: N»** крупным шрифтом — это конкретное число, ради которого человек открыл приложение.
- Кнопка **«Повторять»** — primary-стиль (заливка), ведёт в SRS-флоу флэшкарт.

Один составной бар вместо трёх отдельных шкал — так пропорции считываются одним взглядом, а не сравнением трёх полосок по отдельности.

Источники данных: `progress` (счётчики по состоянию карточек), `review_events`/`progress.due_at` для числа к повторению сегодня.

### 4. Карточка «План обучения» — второстепенный элемент (secondary)

Физически меньше карточки слов, кнопка **«Продолжить»** — secondary-стиль (обводка, не заливка). Два одинаково тяжёлых CTA на одном экране путают, какой из них главный — вес и стиль должны явно показывать, что это не альтернатива «Повторять», а второе, менее частое действие.

Содержимое: `План {title} · {уровень}, урок {N}` — где пользователь остановился.

Источник данных — `learning_plans`/`textbooks` из `3-dictionary-and-learning.md` (фаза 2, ADR-0002). **На MVP-этапе этих данных не существует** — карточка либо не рендерится вовсе, либо показывает состояние «скоро появится» (см. «Состояния» ниже). Появляется в реальном виде только после реализации раздела «Обучение».

### 5. Раздел «Статистика» (отдельно от Dashboard)

Активность по дням — три маленьких графика (small multiples), каждый со своей шкалой: слова / грамматика / задания. Не один общий line-график с тремя сериями — у метрик разный порядок величин (слов обычно на порядок больше, чем грамматических конструкций), и на общей шкале мелкая серия становится нечитаемой у нуля.

Тоже зависит от данных фазы 2 (грамматика, задания) — на MVP-этапе показывать только серию по словам, либо не включать раздел в первую версию вовсе.

## UX-writing

- Сегмент «доступно для изучения», не «не изучено» — избегаем фрейминга долга (большое число невыполненного демотивирует сильнее, чем помогает).
- Число несделанного в этом сегменте текстом можно не выводить вовсе — достаточно доли в шкале, точная цифра не обязана бить в лицо каждый день.

## Состояния экрана

| Состояние | Что показывать |
|---|---|
| `default` | как в описании выше — есть карточки к повторению |
| `всё повторено на сегодня` (due-count = 0, прогресс есть) | не «0», а «На сегодня всё! Вернись завтра» + опциональная кнопка «Позаниматься ещё» (набрать карточки вперёд графика) |
| `новый пользователь` (прогресса ещё нет вообще) | не «0 к повторению» (неправда и демотивирует) — онбординг: короткое объяснение SRS-повторения в одну строку + кнопка «Начать первую тренировку» на первый набор карточек |
| `loading` | скелетон только в зоне карточки слов, не на весь экран |
| `план обучения недоступен` | карточка плана не рендерится (MVP) или показывает «скоро появится» (после реализации фазы 2, но пользователь ещё не выбрал план) |

## User stories и критерии приёмки

### US-1: Просмотр карточки слов
Как пользователь, я хочу увидеть на главном экране, сколько слов изучено, изучается и доступно, чтобы понимать свой прогресс за один взгляд.

- [ ] Сегменты бара пропорциональны реальным количествам, не фиксированы визуально
- [ ] Число «к повторению сегодня» соответствует `progress.due_at <= now()`
- [ ] У пользователя без единого слова в `progress` — экран в состоянии «новый пользователь», не пустой бар с нулями

```gherkin
Given у пользователя 84 изученных слова, 23 изучаются, 12 к повторению сегодня
When он открывает главный экран
Then видит составной бар с пропорциями 84/23/остальное и число "12" крупным шрифтом
```

### US-2: Начало повторения
Как пользователь, я хочу нажать одну кнопку и сразу попасть в тренировку, чтобы не искать её в меню.

- [ ] Кнопка «Повторять» ведёт в SRS-флоу флэшкарт с уже собранной очередью карточек на сегодня
- [ ] Если к повторению 0 карточек — кнопки «Повторять» нет, вместо неё — сообщение «На сегодня всё» (опционально — «Позаниматься ещё»)

```gherkin
Given у пользователя 12 карточек к повторению
When он нажимает «Повторять»
Then открывается экран тренировки с этими 12 карточками в очереди
```

### US-3: Продолжение плана обучения
Как пользователь с активным планом обучения, я хочу одной кнопкой вернуться туда, где остановился.

- [ ] Кнопка «Продолжить» ведёт на последнюю открытую единицу контента (урок/раздел) в рамках выбранного плана
- [ ] На MVP-этапе (пока `learning_plans`/`textbooks` не реализованы) карточка не отображается вовсе — не пустая заглушка на видном месте

```gherkin
Given у пользователя активен план "인하대학교", последний открытый — урок 5 급2
When он открывает главный экран
Then видит карточку "План 인하대학교 · 급 2, урок 5" с кнопкой "Продолжить"
```

### US-4: Просмотр статистики
Как пользователь, я хочу иногда посмотреть, как менялась моя активность по дням, не видя это на каждом открытии приложения.

- [ ] Раздел статистики физически отделён от Dashboard (отдельная вкладка/роут), не часть той же прокрутки
- [ ] Каждая метрика (слова/грамматика/задания) — свой маленький график со своей шкалой, не общий график с тремя сериями

```gherkin
Given пользователь на главном экране
When он переходит в раздел "Статистика"
Then видит три отдельных маленьких графика активности по дням, каждый со своей осью Y
```

## Новые компоненты дизайн-системы

Компоненты, которых ещё нет в `2-design-system.md`/структуре проекта, но требуются для этого экрана — стоит завести как переиспользуемые, не одноразовые под один экран:

- **`SegmentedProgressBar`** — составной прогресс-бар из N цветных сегментов по пропорции. Общего назначения, пригодится всюду, где нужно показать долю 2–3 категорий одним элементом.
- **`PrimaryButton` / `SecondaryButton`** — заливка/обводка, уже подразумевались токенами `2-design-system.md`, здесь впервые оба стиля нужны на одном экране одновременно.
- **`StreakBadge`** — иконка + число дней подряд.
- **`Sparkline`** — маленький график без осей для раздела статистики (small multiples).
