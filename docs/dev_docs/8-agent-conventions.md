# 8. Правила для всех агентов: процесс, код, тексты, стиль Solomon OS

Этот файл — единая база. Её читают и соблюдают Claude, Codex и любой другой агент перед работой над приложением. Если задача противоречит файлу, останавливаются и спрашивают пользователя.

## 1. Перед началом

1. Прочитать `docs/AGENT_HANDOFF.md`: постоянные особенности проекта и журнал выполненных работ.
2. Прочитать `AGENTS.md` в корне: Next.js здесь не «тот, который вы знаете» (версия 16 с изменёнными API). Перед кодом открыть нужный раздел `node_modules/next/dist/docs/` и учитывать предупреждения об устаревании.
3. Для Solomon OS дополнительно: `docs/dev_docs/7-solomon-os.md` (идея, этапы, выбранный стиль).
4. Смотреть соседний код и повторять его: имена, плотность комментариев, приёмы.

## 2. Процесс

- Commit, push, деплой и любые изменения production (Supabase, Vercel) — только когда пользователь прямо сказал. Работаем локально.
- Dev-сервер только на порту 3000 (`pnpm run dev`). Если порт занят чужим сервером, сообщить пользователю; других серверов не запускать.
- Временные файлы, скрипты и скриншоты — только в рабочей папке сессии (scratchpad), не в репозитории и не в `/tmp`.
- Не создавать новые документационные файлы (README, .md), если пользователь не попросил. Исключение: запись в `docs/AGENT_HANDOFF.md` после значимой задачи.
- Никогда не добавлять в git: `content/reference/art-sources/`, `content/reference/inha_workbook_photo/`, черновики иллюстраций, `scripts/__pycache__/`.
- Правки, которые пользователь отложил, записываются в `docs/dev_docs/5-pending-edits.md` и не делаются, пока он не попросит.
- Исправления, которые пользователь прямо просит, делаются сразу, без накопления.
- Малые правки интерфейса проверяются `tsc` и lint; полный прогон тестов и просмотр в браузере — один раз на пакет правок.
- Ответы пользователю — по-русски, коротко и по делу, без пересказа сделанного.

## 3. Код

- Стек: Next.js (App Router), React, TypeScript (строгий), CSS Modules, Vitest + Testing Library. Новые зависимости не добавлять без просьбы.
- Комментарии — только там, где без них неясно «почему». Тип, имя и структура должны читаться сами.
- Файл больше ~300 строк делить: данные, чистая логика (без React), компоненты.
- Чистую логику (проверка ответов, сборка вопросов, правила времени жизни) выносить в функции без React и покрывать тестами.
- Хранилище Solomon OS — только `OsStore` (`src/features/solomonOs/store.ts`) через `useOsStore()`; ключи без префикса, префикс `solomon:` и пользователя добавляет сам стор. Каждое чтение и запись переживают сбой `localStorage` (стор это уже делает).
- Не менять сохранённую структуру существующих ключей (`chat`, `calls`, `task` и др.) без обратной совместимости: у пользователя уже есть данные.
- Серверных запросов, Supabase и ИИ-вызовов в клиентских играх Solomon OS нет, пока пользователь не попросил.
- Перед завершением: `npx tsc --noEmit`, `npx eslint <изменённые пути>`, `npx vitest run`. Падения не маскировать: если что-то не проходит, сообщить с текстом ошибки.

## 4. Тексты и содержание

- Уроки хранятся по7файлам разделов плюс manifest lesson-NN.json. Для чтения использовать `readLessonSource` из scripts/lib/lesson-source.ts: root.pages содержит только оглавление. Править нужный01–07файл в папке урока; не собирать вручную второй полныйJSONи не дублировать содержимое вmanifest. Старые id, toc_section и порядок страниц сохранять.

- Язык интерфейса Solomon OS — корейский, перевод по кнопке RU и по нажатию на реплику. Вопросы тренажёров, где пользователь просил русский, пишутся по-русски.
- Сюжетные тексты пишет только пользователь. Учебную лексику и грамматику не выдумывать: брать из каталога игры (`lessonSticker/clothing/`) или из учебника.
- Корейские формы, частицы и значения проверять по источникам, а не по памяти. Нельзя оставлять в тексте неподтверждённое утверждение.
- Любой пример на корейском — с русским переводом; частицы 을/를, 이/가 и т. п. подбирать функцией (`hasBatchim`, `objectParticle` в `lessonSticker/clothing/buildSentence.ts`), а не вручную.

## 5. Стиль Solomon OS

Выбран вариант 2 «Kali» (`docs/dev_docs/design/solomon-os/variants.html`, `desktop.html`). Основное приложение (бумажная палитра из `2-design-system.md`) и Solomon OS визуально не смешиваются.

### Токены (`src/features/solomonOs/OsTheme.module.css`, класс `.theme`)

| Токен | Значение | Роль |
|---|---|---|
| `--bg` | `#0d1410` | Фон рабочего стола |
| `--panel` | `#0a0f0c` | Верхняя панель |
| `--win` / `--win2` | `#101a14` / `#0e1712` | Окно и боковые панели |
| `--line` / `--line2` | `#1d3326` / `#16261c` | Рамки и разделители |
| `--bright` | `#00ff66` | Акцент, заголовки разделов |
| `--mid` | `#0fbf4f` | Ссылки, второстепенный акцент |
| `--green` | `#22a354` | Мои сообщения, активные кнопки |

| `--text` | `#c9f7d8` | Основной текст |

Новые стили используют только эти переменные (`var(--…)`). Свои цвета допускаются только для самого содержимого (например, образцы цветов одежды из `COLORS`).

### Правила оформления

- Окна — как в Xfce: тонкая рамка `--line`, лёгкое скругление и тень. Иконки рабочего стола заполненные. Для действий словаря пользователь 2026-11-05 выбрал контурный набор2, а для карточек — колоду из набора3 (`gallery-horizontal-end`). Без матричного дождя и сканлиний внутри окон.
- **На ярко-зелёном фоне — только чёрный текст `--ink`** (мои сообщения `--green`, активные кнопки, наведение на ответ).
- Чужие сообщения: фон `#14241a`, текст `#e0f8e8`, скругление 12px, у угла отправителя 4px. Мои: `--green` + `--ink`.
- Варианты ответа и кнопки: фон `#14241a`, рамка `--line`, радиус 8px, при наведении `--green` + `--ink`; перевод внутри — `--soft` (на наведении `#0b3d1f`).
- Корейский текст — с классом `kr`; перевод скрыт до кнопки RU и показывается классом `showRu` (как в `Messenger.tsx`).
- Мелкая подпись — 11–12.5px `--soft`; основной текст — 15px; межстрочный 1.35–1.45.
- Кнопки и ответы — нажимаемая область не меньше 40px по высоте на телефоне.
- Анимации короткие (`pop` 0.2s), с `prefers-reduced-motion: reduce` отключаются.

### Элементы форм (уточнение пользователя 2026-11-04)

- В Solomon OS только кастомные элементы в общей теме: не использовать нативные select/datalist, системные меню выбора и стандартное оформление полей. Для списков — `controls/OsSelect.tsx` с порталом в теме OS, управлением стрелками/Enter/Escape и возвратом фокуса.
- Input/textarea остаются семантическими полями с полным собственным оформлением: appearance:none, общие токены, видимый фокус, без системного resize. Для групп — своё поле-фильтр и компактный выпадающий список существующих групп.
- Интерфейс плотный: отступы между полями8–10px, в панелях8–12px, без дублирования одинаковых кнопок добавления. Переключатели дизайнов маленькие1–7только в предпросмотре, без прокрутки страницы. С05ноября в обычном словаре выбран каталог «Узкие группы», создание/правка — «Чистая заметка» с разделителями вместо рамок вокруг каждого поля. Формы и тренировка открываются модалками, фильтры скрыты под иконкой. Группы на узком окне переходят сверху; выбор своих групп — компактный список под полем, типы — компактные кнопки. Автоперевод из общего словаря только при точном совпадении и без замены ручного ввода.
- В форме заметки фокус input/textarea отмечается только нижней линией, без прямоугольной обводки. Источник перевода — значок ! с подсказкой по наведению/нажатию, без постоянной текстовой подписи. Исходный общий перевод доступен в подсказке и после своей правки; поле можно дописывать, заменять и очищать без автоматического восстановления стёртого.
- Окно создания/правки словаря без затемнения, переносится за заголовок, без ручного изменения размера. Группа выбирается в одной строке: ввод фильтрует список совпадений; +справа виден только для нового названия. Список в портале, без увеличения высоты формы, с отметкой выбранных и клавиатурным управлением. Несколько групп сохраняются; поиск сам по себе не меняет выбор.

### Адаптивность и доступность

- Проверка на ширине 375px (iPhone): нет горизонтальной прокрутки, безопасные зоны `env(safe-area-inset-*)`, поле ввода не уезжает под клавиатуру.
- У интерактивных элементов есть имя (`aria-label` по-русски или видимый текст), у групп ответов — `role="group"` и `aria-label="Ваш ответ"`, у модальных листов — `role="dialog"` и `aria-label`.
- Фокус клавиатурой виден; Enter и пробел работают на всех кнопках.

## 6. Тесты

- Тесты лежат в `tests/` (`solomon-*.test.ts(x)`). Новая логика — отдельный файл тестов рядом по смыслу.
- Время в тестах подменять (`vi.useFakeTimers`, `vi.setSystemTime`), случайность — `vi.spyOn(Math, "random")` или передаваемым параметром.
- Существующие тесты Solomon OS должны проходить без правок; менять ожидания допустимо только когда изменилось сознательно принятое поведение, и об этом пишется в отчёте.
