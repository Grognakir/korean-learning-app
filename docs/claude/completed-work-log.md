# Error-границы (белый экран на проде, требовал перезапуска приложения)

> Статус: выполнено, проверено локально живым throw в RootLayout и в
> странице настроек — оба раза вместо белого экрана показался наш
> error/global-error UI с рабочей кнопкой "Попробовать снова". Задеплоено.

## Контекст

Пользователь сообщил: иногда при открытии прод-версии появляется белый
экран, и помогает только полное закрытие и повторное открытие приложения
(не просто обновление страницы). Приложение — устанавливаемый PWA
(`display: "standalone"`, `appleWebApp.capable: true`) — на айпаде
открывается без браузерного chrome, без адресной строки/кнопки "назад".

Во всём `src/app/` не было НИ ОДНОГО error-boundary файла. Next.js App
Router: `error.tsx` не перехватывает ошибки корневого `app/layout.tsx` —
только `global-error.tsx` может. Корневой layout делает реальный сетевой
`auth.getUser()`/запрос профиля на каждый холодный рендер — на айпаде в
момент повторного открытия PWA после простоя сеть может быть ещё не
готова, фейл `fetch` бросает необработанное исключение прямо в рендере
корневого layout → белый экран без `global-error.tsx`.

## Реализация

- `src/app/global-error.tsx` — Client Component, рендерит собственные
  `<html><body>` с инлайновыми стилями (токены приложения), "Что-то
  пошло не так" + кнопка "Попробовать снова" (`reset()`).
- `src/app/error.tsx` + `error.module.css` — то же для ошибок
  ниже корневого layout, через `Button.module.css`, плюс ссылка на `/`,
  `console.error(error)` для Vercel Runtime Logs.

## Проверка

- `tsc`/`lint`/193 теста зелёные.
- Живой throw в RootLayout и в обычной странице — оба раза сработал
  нужный error UI, убран после проверки.
- Задеплоено в прод.

# Убрать дублирующиеся auth/profile-запросы (тормозила навигация между разделами/уроками)

> Статус: выполнено и задеплоено в прод (коммит `d0348bd`). Тёплая
> навигация между разделами/уроками 190-240мс вместо потенциальных
> 3× `auth.getUser()` + 3× `profiles`-запросов на переход.

## Контекст

Жалоба: переключение между разделами/уроками/учебниками (особенно на
айпаде) занимает ~1-1.5 секунды.

Причина — дублирующиеся запросы аутентификации и профиля на каждую
навигацию: у `/learning` нет `layout.tsx`, поэтому каждый `page.tsx` сам
вызывает `requireUser()`/`requireUserWithProfile()`/`getLearningContext()`
— а корневой `src/app/layout.tsx` тоже делает независимый
`auth.getUser()` + запрос профиля. Ни `createClient()`, ни
`auth.getUser()`, ни запрос `profiles` нигде не были мемоизированы в
рамках одного запроса — на одну навигацию уходило минимум 2-3 отдельных
сетевых `auth.getUser()` и 2-3 запроса `profiles`.

## Реализация — мемоизация на request через `React.cache()`

- `src/lib/supabase/server.ts` — `createClient` обёрнут в `cache()`.
- `src/features/auth/requireUser.ts` — новые мемоизированные
  `getAuthUser()` и `getProfileRow(userId)`; `requireUser()`/
  `requireUserWithProfile()` переписаны поверх них.
- Заменены дублирующиеся точки на общие хелперы: `src/app/layout.tsx`,
  `getLearningContext.ts`, `getActiveLanguage.ts`, `src/app/page.tsx`,
  `settings/page.tsx`, `dictionary/page.tsx`, все 4 файла
  `src/app/learning/plans/**`.

## Проверка

- `tsc`/`lint`/`test` зелёные.
- Браузер: навигация ощутимо быстрее, количество auth/profile-запросов
  на навигацию снижено с ~4-5 до 1+1.
- Задеплоено в прод.

# Достроить уроки 1 и 2 учебника 2급 (все разделы)

> Статус: выполнено и проверено в проде. Уроки 1 и 2 теперь содержат все
> 8 разделов каждый. Добавлены 3 новых типа блока: `comprehension_exercise`,
> `writing_exercise`, `pronunciation`.

## Контекст

Урок 1 и урок 2 имели расшифрованными только 준비하기1/2. По фото
교재 구성표 у каждого урока 2급 всего 8 разделов. Пользователь подтвердил
через AskUserQuestion: объём — только уроки 1-2, все разделы.

## Технический риск — учтён

`page_index` в `textbook_pages` сквозной по всей книге через
`startIndex`-цепочку в `scripts/import-textbook.ts`; `upsert` по
`(textbook_id, page_index)` не удаляет старые строки на прежних
индексах при росте числа страниц урока. Перед финальным импортом (и
локально, и в проде) все существующие строки `textbook_pages` для
`inha-2` удалялись через REST DELETE, затем импорт с нуля.

## Проверка

`tsc`/`lint`/`test` зелёные, браузер — оба урока со всеми разделами,
`grammar_exercise` интерактивно проверен, прод проверен через REST.
